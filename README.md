# 3D UAV Cooperative Capture-Radius Pursuit

This repository contains the reproducible baseline for **partial-observable,
obstacle-aware, multi-UAV 3D capture-radius pursuit-evasion**.

## Current result

- Four defenders pursue one evasive target in a `20 m x 20 m x 10 m` world.
- Cylindrical obstacles, target occlusion/dropout, noisy local detections,
  delayed/dropped teammate messages, and belief-state observations are enabled.
- A safe capture is recorded when at least one defender enters
  `r_capture = 0.80 m` without a previous obstacle collision, teammate
  collision, or boundary violation.
- The warm-start CTDE-MAPPO policy reached `100% +/- 0%` safe capture and
  `0% +/- 0%` collision on 900 locked test episodes across three training
  seeds. The complete evidence is in
  `results/CAPTURE_RADIUS_FINAL_REPORT.md`.

This is a simulation capture-radius result. It is not a claim of physical
impact, net capture, hardware flight, SITL, or real-world perception.

## Repository layout

```text
src/encirclement3d/
  pursuit_env.py          # partial-observation 3D capture-radius environment
  pursuit_controllers.py  # pursuit, prediction, encirclement, and CBF baselines
  learning.py             # shared actor-critic used by BC and MAPPO
  environment.py          # common 3D world and obstacle primitives
  pybullet_env.py         # optional Crazyflie/PyBullet dynamics backend
scripts/
  train_capture_radius_behavior_cloning.py
  train_capture_radius_mappo.py
  evaluate_capture_radius_mappo.py
  run_capture_radius_pursuit.py
  ...                     # PowerShell/BAT launchers and PyBullet transfer tools
configs/
  capture_radius_*.yaml   # primary experiment configurations
tests/                    # unit, environment, and CLI regression tests
```

Generated result directories are intentionally excluded from Git. The final
report is the only tracked result artifact; checkpoints and TensorBoard logs
are regenerated by the commands below.

## Environment

Use the RTX 4060-compatible Conda environment:

```powershell
conda env create -f environment.yml
conda run --no-capture-output -n uav-encirclement-gpu python -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0))"
```

The optional PyBullet backend uses the pinned source under `third_party/` and
`pybullet=3.25`. The vendored source is retained for deterministic simulator
tests; the release archive is not tracked.

## Reproduce the primary experiment

Run the regression suite first:

```powershell
conda run --no-capture-output -n uav-encirclement-gpu python -m pytest -q
```

Train the local-information behavior-cloning warm start:

```powershell
.\scripts\run_capture_radius_behavior_cloning.ps1 `
  -Config configs/capture_radius_behavior_cloning_dev.yaml `
  -Output results/capture_radius_behavior_cloning_dev
```

Train MAPPO from that checkpoint:

```powershell
.\scripts\run_capture_radius_mappo.ps1 `
  -Config configs/capture_radius_mappo_warmstart_dev.yaml `
  -Output results/capture_radius_mappo_warmstart_dev `
  -InitializeFrom results/capture_radius_behavior_cloning_dev/checkpoint.pt
```

Evaluate a frozen policy on a new output directory:

```powershell
.\scripts\evaluate_capture_radius_mappo.ps1 `
  -Config configs/capture_radius_pursuit_dev.yaml `
  -Checkpoint results/capture_radius_mappo_warmstart_dev/checkpoint.pt `
  -Output results/capture_radius_eval `
  -Seed 610001 -Episodes 100 -Device cpu -UseCbf
```

TensorBoard:

```powershell
.\scripts\start_tensorboard.ps1 -LogDir results -Port 6006
```

Equivalent `.bat` launchers are provided for Command Prompt.

## Scope of the next phase

The next research stage is defined in
`NEXT_PHASE_CAPTURE_ROBUSTNESS_TODOLIST.txt`. It upgrades the frozen baseline
in this order: harder target maneuvers, unseen obstacle layouts, inertial and
actuator dynamics, learned perception/tracking, and recurrent belief-aware
multi-agent control. Kinematic, PyBullet, and future hardware results must be
reported as separate evaluation domains.

## Stage 2 observation/communication baseline

Stage 2 adds configurable observation timestamp, confidence, covariance, burst
occlusion, local measurement delay, message delay, packet loss, and link loss.
The protocol is documented in `OBSERVATION_COMMUNICATION_PROTOCOL.md` and the
locked-test configuration is
`configs/capture_radius_observation_communication.yaml`. The current Pure
Pursuit + CBF result is summarized in
`results/OBSERVATION_COMMUNICATION_STAGE2_REPORT.md`; it is a kinematic rule
baseline, not the final learned method. The next implementation target is a
predictor trained only from these local observation histories, followed by
Recurrent-MAPPO ablations.

The first Stage 3 artifact is the local-history prediction pipeline:
`PREDICTION_DATASET_PROTOCOL.md`,
`scripts/generate_prediction_dataset.py`, and
`scripts/evaluate_prediction_baselines.py`. Its locked-test baseline is
summarized in `results/PREDICTION_STAGE3_BASELINE_REPORT.md`.
