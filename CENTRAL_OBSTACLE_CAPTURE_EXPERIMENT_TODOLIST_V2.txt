部分可观测三维中央障碍区多无人机协同围捕实验计划
版本：2026-08-20

======================================================================
一、实验目标
======================================================================

1. 核心研究目标

在部分可观测三维环境中，将圆柱、立方体和墙体组成的混合障碍区布置在场地中央，
使多架追捕无人机与持续运动的逃逸目标分别从障碍区两侧出发。无人机需要在不越界、
不碰撞的前提下协同绕行或穿越障碍区，最终至少一架无人机进入目标的固定捕获半径，
完成 Safe Capture。

2. 本实验真正要验证的问题

不是单独展示一段好看的动画，而是验证：

    在中央混合障碍、部分观测、通信延迟、目标逃逸和边界约束同时存在时，
    多无人机策略能否稳定完成“安全穿越 + 协同接近 + 捕获”。

3. “所有主体顺利过障碍物”的严格定义

    仅进入中央障碍区不算完成穿越；
    从左侧出发的主体必须到达 obstacle_zone_x 的右边界之外；
    从右侧出发的主体必须到达 obstacle_zone_x 的左边界之外；
    轨迹全过程不得进入障碍物实体或越过世界边界。

4. 研究边界

    当前阶段是三维仿真中的 capture-radius success，不等同于真实飞行器的机械接触、
    网捕或实体抓捕。实体捕获接口、飞控闭环和实飞验证另列为后续工作，不混入本阶段结论。

======================================================================
二、固定实验定义
======================================================================

1. 世界与安全参数

    世界范围：x,y ∈ [-10,10] m，z ∈ [0.5,10] m；
    捕获半径：r_capture = 0.80 m，物理判据固定不变；
    障碍安全膨胀：drone_radius + safety_margin，初始 safety_margin = 0.35 m；
    中央障碍区：obstacle_zone_x = [-2.5, 3.0] m；
    初始侧向距离：4.5-6.0 m，先通过可达性检查再运行；
    所有主体保留至少 1.0 m 的边界缓冲，不允许依靠撞边反弹捕获。

2. 成功判据

    Capture：min_i ||p_i - p_target|| <= 0.80 m；
    Safe Capture：首次进入捕获半径前无障碍碰撞、机间碰撞和边界违规；
    Crossing Success：要求穿越的主体全部到达障碍区对侧；
    Showcase Success：Safe Capture 且满足当前场景规定的 Crossing Success。

3. 统计与可视化分离

    PNG/GIF/MP4 只用于展示完整过程；
    正式结论必须来自固定 seed block 的 CSV/JSON 统计；
    raw action 与 CBF action 分开报告，不能把 CBF 的安全修正全部归因于策略网络。

======================================================================
三、场景递进设计
======================================================================

S0：几何与判据烟雾测试

    [ ] 只验证圆柱、立方体、墙体的 footprint、碰撞和 clearance；
    [ ] 验证初始点、目标点、边界和路线可达性；
    [ ] 验证“进入中央区”和“到达对侧”被分别记录；
    [ ] 不进行训练，不把渲染成功当作策略成功。

S1：固定中央混合障碍，追捕侧单向穿越

    [ ] 追捕无人机在左侧，目标在右侧，初始距离 4.5-6.0 m；
    [ ] 障碍物固定为 1 个圆柱 + 1 个立方体 + 1 面墙；
    [ ] 目标持续向右逃逸，追捕无人机必须穿过中央障碍区；
    [ ] 作为现有 checkpoint 的第一项回放与展示基线。

S2：固定中央混合障碍，双向穿越

    [ ] 追捕无人机改在右侧，目标在左侧；
    [ ] 目标朝障碍区及对侧运动，目标也必须完成穿越；
    [ ] 4 架追捕无人机和目标都必须满足 crossing completion；
    [ ] 用于验证场景方向改变后策略是否仍然有效。

S3：中央区域随机混合障碍

    [ ] 随机改变圆柱、立方体、墙体数量、位置、尺度和墙体方向；
    [ ] 每个地图先做保守路线搜索，无法通过的地图直接拒绝；
    [ ] 训练、验证、测试使用互不重叠的 seed block；
    [ ] 保留固定 S1/S2 作为回归场景，不允许随机化覆盖它们。

S4：鲁棒性压力测试

    [ ] 增加观测丢失、观测噪声、通信延迟和目标转向；
    [ ] 逐项增加困难因素，每次只新增一个主要变量；
    [ ] 记录失败原因：超时、碰撞、越界、未穿越或未捕获；
    [ ] 只有 S1-S3 通过后才进入 S4。

======================================================================
四、方法与训练决策
======================================================================

1. 固定比较方法

    [ ] Formal F2 checkpoint + CBF；
    [ ] Dynamic Encirclement rule expert + CBF；
    [ ] Recurrent Behavior Cloning + CBF；
    [ ] Recurrent MAPPO + CBF；
    [ ] 需要时额外报告不使用 CBF 的 raw action。

2. 是否重新训练的规则

    [ ] 先用现有 checkpoint 在 S1 做几何修正后的回放；
    [ ] 若失败来自代码、碰撞几何、边界或无路可走，先修正环境，不重训；
    [ ] 若 S1 可行但 S2/S3 出现稳定分布外失败，再启动课程式 BC -> MAPPO；
    [ ] 课程顺序：open -> cylinder -> cylinder_box -> mixed -> 双向 mixed -> 随机 mixed；
    [ ] 正式结论至少使用 3 个独立训练 seed，并在未参与调参的 locked-test 上评估。

3. 训练产物

    [ ] YAML 配置；
    [ ] checkpoint.pt；
    [ ] TensorBoard 日志；
    [ ] 环境、依赖、GPU 和源代码 hash；
    [ ] 每回合 scenario metadata、seed、障碍物几何和终止原因。

======================================================================
五、Todolist（按执行顺序）
======================================================================

阶段 A：冻结定义与代码接口

    [ ] A1. 固定世界边界、捕获半径、障碍安全膨胀和中央区域范围；
    [ ] A2. 固定 Cylinder/Box/Wall 的统一几何记录格式；
    [ ] A3. 完成 spawn validity、obstacle overlap、boundary 和 route feasibility 检查；
    [ ] A4. 让 trajectory.npz 保存障碍物形状、尺寸、中心和方向；
    [ ] A5. 让 episode.json 保存 scenario、seed、side、crossing requirement 和终止原因；
    [ ] A6. 为随机回合和 showcase 回合提供一致的 metadata 字段。

阶段 B：先验证 S1，不急于重训

    [ ] B1. 用现有 F2 + CBF 跑 S1 的 20 回合分布探针；
    [ ] B2. 检查 4 架无人机是否进入中央区并完成对侧穿越；
    [ ] B3. 检查目标是否持续移动、无障碍碰撞、无越界；
    [ ] B4. 输出一条成功轨迹、一条失败轨迹及对应 JSON/CSV；
    [ ] B5. 若 S1 仍稳定失败，先定位几何、观测范围和 CBF 问题。

阶段 C：实现并验证 S2

    [ ] C1. 支持 defender_side=left/right；
    [ ] C2. 目标在 crossing-required 场景中朝对侧运动；
    [ ] C3. 使用“到达对侧”而不是“进入中央区”作为 crossing 指标；
    [ ] C4. 先跑 rule expert + CBF，确认 S2 本身可解；
    [ ] C5. 再评估现有 checkpoint，记录分布外失败，不直接宣称鲁棒。

阶段 D：课程式训练（仅在 C 阶段证明需要时启动）

    [ ] D1. 保留原随机回合，同时逐步提高中央 showcase 比例；
    [ ] D2. 后期课程加入 defender_sides=[left,right] 和 target crossing；
    [ ] D3. 先训练 BC，再用 BC 初始化 recurrent MAPPO；
    [ ] D4. 用 held-out S1/S2 validation 选择 checkpoint，不使用 locked-test 调参；
    [ ] D5. 使用至少 3 个训练 seed 重复训练。

阶段 E：实现 S3 随机中央障碍

    [ ] E1. 随机化障碍物数量、位置、尺寸和墙体方向；
    [ ] E2. 每张地图保证至少一条满足安全间隙的路线；
    [ ] E3. 生成固定 train/validation/test seed 清单；
    [ ] E4. 输出按布局、方向、目标速度和可观测性分组的结果；
    [ ] E5. 与固定 S1/S2 结果并列报告，避免只挑最好看的场景。

阶段 F：正式评估与媒体

    [ ] F1. 统计 Safe Capture Rate、Capture Rate、Crossing Rate；
    [ ] F2. 统计障碍碰撞率、机间碰撞率、边界违规率和最小 clearance；
    [ ] F3. 统计捕获时间、路径长度、绕行比、可见比例和 CBF 修正量；
    [ ] F4. 分开输出 raw/CBF 两套结果；
    [ ] F5. 生成俯视图、三维视图、指标曲线、PNG、GIF 和 H.264 MP4；
    [ ] F6. 捕获帧显示固定真实捕获圈、绿色高亮、冻结帧和 CAPTURE CONFIRMED；
    [ ] F7. 报告中明确标注“simulation capture-radius success”。

======================================================================
六、阶段验收标准
======================================================================

最低可展示标准：

    [ ] S1 至少有一条完整成功轨迹；
    [ ] 无碰撞、无越界，并能导出可复现的 PNG/GIF/MP4；
    [ ] JSON/CSV 能证明捕获发生在 0.80 m 半径内。

研究结论标准：

    [ ] S1、S2、S3 均有固定 seed block；
    [ ] 至少 3 个训练 seed；
    [ ] 统计同时报告捕获、穿越、安全和失败原因；
    [ ] 不把单条成功视频当成泛化结论；
    [ ] 明确当前仿真与实体捕获之间的差距。

======================================================================
七、最短执行路线
======================================================================

    1. 先完成 A1-A6 和 S0 几何测试；
    2. 用现有 checkpoint 完成 B1-B5；
    3. 用 rule expert 验证 S2 可解，再评估 checkpoint；
    4. 只有确认存在稳定分布外失败，才执行 D1-D5 重训；
    5. 最后实现 S3、S4 和正式多 seed 评估；
    6. 统计通过后再制作最终论文风格视频。

本计划的核心原则：先保证任务定义、几何、穿越判据和统计可信，再追求画面美观；
先验证现有模型能否解决固定场景，再决定是否增加训练复杂度。
